Warm-up

How would you find the best exam timetable?

70 courses share 15 exam slots, several exams at a time in different rooms. Any student with two exams in the same slot complains. Find the timetable with the fewest complaints.

Idea
Try every timetable and keep the best one.
1570 ≈ 2.1 × 1082

possible timetables: each course can go in any of the 15 slots

  • Atoms in the observable universe: about $10^{80}$.
  • Checking a billion timetables per second takes $2\times10^{73}$ seconds.
  • That is about $5\times10^{55}$ times the age of the universe.
Today
Algorithms that find a good timetable anyway, while looking at almost none of them.
Two ways to solve a problem

Constructive algorithms vs local search

Constructive

  • Builds the solution from scratch, piece by piece.
  • When it finishes, you have the answer.

Bisection (L03) · Newton’s method (L04) · Gaussian elimination (L12) · least squares (L13)

Local search

  • Starts with a complete solution, probably a bad one.
  • Improves it with many small changes.
  • Stops when it runs out of improvements, or of time.

Timetabling · route planning · packing · code breaking

When to reach for it
The solutions are discrete, there are astronomically many of them, and no formula builds the best one.
Before writing any code

The three pillars of local search

$S$

State

A candidate solution: complete, but maybe bad.

three point indices · a list of 70 slot numbers

$f(S)$

Objective function

One number that says how good $S$ is.

maximise a score or minimise a cost. Pick one and stay consistent.

$N(S)$

Neighbor

A slightly modified version of $S$.

too small a change and you crawl; too big and you are guessing at random

Habit
For every new problem, name the three pillars first. The code is fifteen lines; choosing the pillars is the real work.
The greedy approach

Hill climbing

  1. Start with a random solution: the current state.
  2. Look at all (or some) of its neighbors.
  3. Evaluate them with the objective function.
  4. If a neighbor is better, move there.
    If none is better, stop: you are on a peak.

It is greedy: it only ever moves uphill.

The same skeleton every time

Hill climbing in code

def optimize(initial_state, score, perturb, iterations=10000):
    current_state = initial_state
    current_score = score(current_state)

    for i in range(iterations):
        trying_state = perturb(current_state)  # a random neighbor
        trying_score = score(trying_state)

        if trying_score > current_score:        # better? move there
            current_state = trying_state
            current_score = trying_score

    return current_state, current_score

For each new problem you write two functions:

  • score(state): the objective
  • perturb(state): returns a random neighbor

optimize never changes.

Stochastic hill climbing
We try one random neighbor per iteration instead of all of them, and stop after a fixed number of tries.
Example A

The biggest triangle

We are given 500 random points. Choose three of them so that their triangle has the largest area.

np.random.seed(13)
n = 500
x = np.random.randn(n)*2-1
y = np.random.randn(n)*2-1
plt.plot(x, y, '.r')

Area from the three corners (the shoelace formula):

$$A=\tfrac12\left|\,x_1y_2+x_2y_3+x_3y_1-y_1x_2-y_2x_3-y_3x_1\,\right|$$

Example A · think before you code

Four questions

Q1With $n$ points, how long does brute force take?
Every triple: $\binom{500}{3}=20{,}708{,}500$ triangles, $O(n^3)$. Fast in C, about a minute in pure Python. This time we can check the answer.
Q2What is our state?
Three point indices (i, j, k), e.g. (3, 6, 5). Indices, not coordinates: the points never change.
Q3How do we move to a neighbor?
Replace one of the three indices with a random point. Each state has $3\times499$ neighbors.
Q4How do we decide whether to keep it?
Keep it if the area got bigger. We are maximising.
Example A · the two problem-specific functions

Score and perturb

def triarea(x1,y1, x2,y2, x3,y3):
    # shoelace formula
    return 0.5*abs(x1*y2 + x2*y3 + x3*y1 - y1*x2 - y2*x3 - y3*x1)

State = Tuple[int, int, int]           # three point indices

def score(state: State) -> float:
    s1, s2, s3 = state
    return triarea(x[s1], y[s1], x[s2], y[s2], x[s3], y[s3])

def perturb(state: State) -> State:
    idx = np.random.randint(0, 3)        # which corner moves
    ret = [s for s in state]             # a copy, not the original
    ret[idx] = np.random.randint(0, n)   # any of the n points
    return tuple(ret)

best_state, best_score = optimize((3, 6, 5), score, perturb,
                                  iterations=100000)
  • score: the triangle’s area. Bigger is better.
  • perturb: move one corner to a random point.
  • optimize: unchanged from the last slide.
Why a tuple?
A tuple cannot be changed in place, so perturb can never damage the current state by accident.

Example B

Scheduling exams

Put 70 exams into 15 time slots so that as few students as possible have two exams at once.

A slot is a time, not a room
Monday 9:00 (slot 0) runs five exams at once, each in its own room.
  • Sharing a slot is fine, unless a student takes two of those exams. Nobody can sit two exams at once.
  • 70 slots would mean no clashes, but 70 sessions of exams.
  • With 15, exams must share. The question is which ones.
  • We assume there are enough rooms: only clashes count.

Example B · think before you code

Four questions

Q1With $n$ classes and $k$ slots, how long does brute force take?
Each class picks one of $k$ slots: $k^n$ timetables. $15^{70}\approx2\times10^{82}$. Not slow: impossible.
Q2What is our state?
A list of 70 slot numbers: state[i] is the slot of class $i$. Start with [1] * 70.
In [3, 0, 14, 3, …], classes 0 and 3 share slot 3.
Q3How do we move to a neighbor?
Pick one class and move it to a random slot. Every list is a legal timetable, so nothing can break.
Q4What is our cost function?
Total complaints, which we minimise:
$\displaystyle f(S)=\sum_{i<j}[\,S_i=S_j\,]\cdot\text{student}[i][j]$
Example B · the code

Perturb and score

n_time_slot = 15
n_class = 70
initial_state = [1] * n_class         # everyone in slot 1

def perturb(state):
    ret = state.copy()                 # never edit the input
    idx = np.random.randint(n_class)   # pick a class
    ret[idx] = np.random.randint(n_time_slot)  # new slot
    return ret

def score(state):                      # lower is better
    complaints = 0
    for i_class, timeslot in enumerate(state):
        for j_class in range(i_class + 1, n_class):
            if state[j_class] == state[i_class]:  # same slot
                complaints += student[i_class, j_class]
    return complaints

The only change to optimize:

-   if trying_score > current_score:
+   if trying_score < current_score:
  • Start: all 70 classes in slot 1, so all $\binom{70}{2}=2415$ pairs clash, about 60,000 complaints.
  • score visits 2,415 pairs and runs 50,000 times: tens of seconds in Python.

Two bugs worth knowing

Pitfalls

1 · Editing the state in place
def perturb(state):
    ret = state       # not a copy: the same list
    ret[idx] = ts     # current_state changes too!
    return ret

A rejected move still changes current_state. The state drifts away while current_score describes a state you no longer have. Lists need .copy(). Tuples are safe.

2 · Seeding too late
student = np.random.randint(0, 100, (70, 70))
np.random.seed(222)   # too late: already drawn

This is in the original notebook. The seed does nothing to the matrix, so everyone solves a different problem and gets a different answer. Seed first, then draw.

Limitations of hill climbing

Why hill climbing gets stuck

or click anywhere on the landscape. A neighbor is any point within ±25 steps.

Local optimum: the top of a small hill. Every step goes down, so you stop, even though a taller mountain is one valley away.

Plateau: every neighbor has the same score. Nothing is “better”, so the climber never moves.

The cheapest fix

Random restarts

Run hill climbing many times from different random starts and keep the best result.

On this landscape one climb reaches the top about 1 time in 4. The best of 20 almost always does: $1-0.75^{20}\approx99.7\%$. It costs 20× the time, and it is still not a guarantee.

Other techniques

Getting past local optima

Simulated annealing

Concept. Sometimes you have to go downhill to cross a valley to a higher mountain.

Hot (early): accept worse moves freely and explore. Cold (late): accept only better moves and refine.

Tabu search

Concept. Don’t walk in circles.

Keep a “tabu list” of your last $N$ moves. You may not undo them or revisit a state you just left.

Genetic algorithms

Concept. Evolution: survival of the fittest.

Keep a population (say 50 solutions). Select the best, cross parents over into a child, mutate the child at random.

Watch: local search on the travelling-salesman problem (visit every city while keeping the total distance short).

Simulated annealing not in the final exam

Sometimes accept a worse move

For a cost we minimise, a move that is worse by $\Delta>0$ is accepted with probability

$$P(\text{accept})=e^{-\Delta/T}$$

  • Hot (large $T$): almost every move is accepted. Explore the map.
  • Cold ($T\to0$): only better moves. Plain hill climbing. Refine.

Cool a little every iteration: $T_k=T_\text{start}\,\alpha^k$ with $\alpha=(T_\text{end}/T_\text{start})^{1/(N-1)}$. The notebook uses $T_\text{start}=50$, $T_\text{end}=0.01$ and $N=50{,}000$, so $\alpha\approx0.99983$.

Simulated annealing · the code (trimmed from the notebook)

Hill climbing with a different if

def simulated_annealing(initial_state, score_fn, perturb_fn,
                        n_iterations=50000, T_start=50.0, T_end=0.01):
    current_state = initial_state.copy()
    current_score = score_fn(current_state)
    best_state, best_score = current_state.copy(), current_score
    alpha = (T_end / T_start) ** (1.0 / max(1, n_iterations - 1))
    T = T_start

    for i in range(n_iterations):
        candidate_state = perturb_fn(current_state)
        candidate_score = score_fn(candidate_state)
        delta = candidate_score - current_score     # > 0 means worse

        if delta <= 0 or np.random.rand() < np.exp(-delta / T):
            current_state, current_score = candidate_state, candidate_score

        if current_score < best_score:               # remember the best
            best_state, best_score = current_state.copy(), current_score

        T *= alpha                                  # cool down

    return best_state, best_score

Same perturb and score as before.

It keeps best_state because the current state is allowed to wander away from the best one.

Summary

What to take away

  • Local search starts from a complete solution and improves it with small changes.
  • Name the three pillars first: state, objective function, neighbor.
  • Hill climbing: perturb → score → keep it if it is better. > maximises, < minimises; nothing else changes.
  • Brute force: $O(n^3)$ for the triangle (survivable), $k^n$ for scheduling (hopeless).
  • Hill climbing gets stuck on local optima and plateaus. Fixes: random restarts, simulated annealing, tabu search, genetic algorithms.
  • None of these guarantee the global optimum. You get a good answer, not a proof.
